# AGENTS.md

Guidance for AI agents working in this repository. NEVER create document files unless explicitly asked.

## Key Design Choice (Maintained manually, AI should NEVER update this section)

- CoC:
    - multi-repo support is required. Never design or implement a feature that would break multi-repo scenario.
    - copilot-sdk wrapper should NEVER add a sendFollowUp method or something similar. copilot-sdk-wrapper layer or above should NEVER try to add keep-alive/session-object cache.
    - Prefer use file path in the prompt instead of expanding the prompt with file's content.

## Repo Layout (one-liner)

npm workspaces monorepo for published Node packages including `coc-workflow`, `forge`, `coc`, `coc-client`, `coc-agent-sdk`, `coc-memory`, `deep-wiki`, `coccontainer`, and `coc-connector` (consolidated Teams + WhatsApp messaging connectors). The root `Dockerfile` + `docker/` + `deploy/tenant/` ship the server as `ghcr.io/plusplusoneplusplus/coc` (loopback-bound by policy; see `packages/coc/test/docker/`).

## Hard Invariants (apply even before reading the skill)

- **Multi-repo:** every feature must support multiple workspaces.
- **Diff providers:** Forge local and supplied remote facades share `createPatchDiffProvider`; loaders retain transport and per-file rendering semantics. PR/iteration factories require explicit workspace, host and provider-qualified repository identity, separate from transport routing aliases. Capture Rust store continuations before authenticated I/O; refresh/disposal revoke delayed results. Authentication stays in TypeScript.
- **Local patch cancellation:** Forge `LocalPatchOptions.signal` cancels one Rust request and its host/WSL execution, not the shared store. Retire tickets, listeners and WSL timers on every outcome; preserve the caller's abort reason and ordinary Git/native errors.
- **Repo-scoped data:** all per-repo runtime data lives under `~/.coc/repos/<workspaceId>/`; resolve paths with `getRepoDataPath(dataDir, workspaceId, filename)`. Never add new top-level dirs under `~/.coc/` for per-repo data.
- **Saved plan links:** plan prompts require the saved file's exact absolute path in reply links, with forward slashes and angle-bracket Markdown destinations. Never convert managed plan paths to repository-relative `../` paths; file access checks remain unchanged.
- **Desktop browsers:** engine and shared web-page zoom preferences in `desktop-browser.json`, and `browser/electron` / `browser/webview2` profiles, are installation-wide desktop data, not workspace-server preferences. Zoom uses native content APIs (50-200%, 25-point steps, default/reset 100%) across URL guests and windows in one desktop process; independent processes do not receive live broadcasts. Electron is the default; WebView2 is Windows x64 opt-in. Local HTML previews use Electron guests and share the browser host manager (`file` sources, isolated in-memory session); full SPA reloads reopen persisted HTML tabs from disk and reset their page history/scroll. Engine changes affect new views only; confirmed per-engine cleanup coordinates all desktop windows and excludes file previews. Page zoom excludes the SPA, editors, terminals, HTML previews and system browser.
- **Desktop history persistence:** `browser-view-host.ts` owns one main-process `BrowserHistoryStore` at `<desktopDataDir>/browser/history.json`, shared by the browser manager across windows/workspaces. Host `visited`/`titleUpdated` events record URL sources; file previews and state snapshots/replays never record. Both engines record completed main documents and committed same-document navigation, including popups. WebView2 tracks navigation IDs and emits explicit history events from its native helper. Title updates cannot create entries. Saves serialize and publish only after atomic rename; failures reject and remain visible in queries. Shutdown drains queued saves. Engine contributions preserve the other engine's metadata during confirmed profile cleanup. History IPC requires a registered exact-source SPA main frame; change/error invalidations reach registered windows without carrying history data. Main owns hourly retention maintenance and stops it before shutdown. Main-owned `suggest(search)` ranks the full retained URL/title index before limiting to eight; prefix completions preserve URL case. `query` retains recency pagination for the History panel.
- **Desktop webviews:** only registered main SPA windows enable `webviewTag`. `coc-desktop/src/browser-webview-guard.ts` authorizes exact-source, owner-bound, single-use attachment tokens, replaces renderer preferences with sandboxed settings, and binds navigation policy before guest loading. File attachments require a pending main-validated HTML path. The SPA's app-level `BrowserWebviewLayer` retains web and HTML guests across workspace remounts; DOM overlays stay above them. Tokens identify attachments, not profile storage.
- **Desktop upgrades:** release, retained-update and failure dialogs keep a manual installer download independent of automatic updating. Resolve assets from the selected release/channel for the host platform and architecture, validate HTTP(S) URLs, and open the system browser through `shell.openExternal`; manual download must not start the updater or launch an installer.
- **Browser control page engine:** `BrowserHostManager.withControlPage` requires the exact owner/view/session key and excludes file previews. Its per-view queue serializes whole input sequences and rejects on abort, close, crash or 30s including queue time; cancellation retains in-flight serialization and completes dispatched releases. Input activates the selected hosted view; Electron focuses its exact guest element and WebView2 transfers native focus. Explicit frame keys require visible ancestors, preserve the active element/selection and exclude descendant-frame focus. Default-off `browserControl.framesEnabled` adds bounded frame snapshots and private contexts/sessions; frame refs bind view/document generations. Shared document-local clipping respects root/body overflow propagation and out-of-flow containing blocks, and verified OOPIF clicks use their private session. Default-off `browserControl.richPasteEnabled` additionally permits bounded `paste_html` into an already-focused editable selection. Native HTML/plain clipboard writes serialize across desktop views; nonempty clipboard replacement requires explicit consent, reads no old contents, and leaves the supplied payload in place. Paste observes trusted delivery, not editor persistence; post-dispatch errors have unknown outcomes and must not auto-retry. Navigation/detachment revoke late results. Keep DOM injection self-contained, debugger transports main-only and clone policy owner-scoped. Unsupported runtimes fail without engine switching or security changes.
- **Work items:** create/update via `POST http://localhost:4000/api/workspaces/<workspaceId>/work-items` — never write `work-items/*.json` files directly.
- **Warm client keep-alive (client process only):** `coc-agent-sdk` and above MAY keep a provider *client process* warm between turns, keyed by `(provider, workingDirectory)`, for a short idle TTL (`COC_WARM_CLIENT_TTL_MS`, default `300000`ms; `0` disables warming entirely). A fresh session is still created/resumed per turn on the warm client — never cache *session objects* and never add `sendFollowUp`. Warm clients are torn down on abort/interrupt/error, on TTL expiry, and on SDK `cleanup()`/`dispose()`. Providers that cannot stay warm (Claude, whose `query()` spawns per turn) fall back to cold-start transparently. See `WarmClientRegistry` in `coc-agent-sdk`. The SPA prewarms the client while the user types a follow-up, debounced by `COC_WARM_PREWARM_DEBOUNCE_MS` (default `500`ms; resolved on the server and surfaced via runtime config).
- **Model resolution order:** `task.config.model` > `PerRepoPreferences.defaultModels[mode]` > `defaultModel` > CLI default.
- **Copilot runtime pin:** SDK `1.0.9` and CLI `1.0.78` are pinned in npm manifests and lockfile; Copilot child processes disable CLI auto-update so a cached runtime cannot supersede the installed CLI.
- **Mixed MCP OAuth:** host-token routing must preserve the client's default OAuth storage policy. Host-injected Teams tokens stay ephemeral. Generic chat OAuth callbacks and unmanaged runtime login require the existing `mcpOauth.enabled` opt-in; native Teams sign-in and pending routes remain available when it is off. With the flag on, generic runtime OAuth persists in normal CLI mode and stays isolated in SDK empty mode. Real-runtime tests inspect the native store as well as fixture files and delete only unique synthetic resource keys.
- **Entra MCP compatibility:** CoC-created Copilot child processes default `COPILOT_ENTRA_ONEAUTH_SCOPE_BINDING_MODE` to `allow_unbound_scopes`, relaxing broker resource binding for all MCP servers in the process. Explicit client/host values override the default; caller-owned connection environments and in-process runtimes remain unchanged.
- **Copilot direct HTTP credentials:** default to `cli-config` with `active-cli-account`; read the exact stored account key per request, preserving bare or HTTPS URL hosts for token lookup and normalizing snapshots to hostnames. File lookup shares SDK validation and precedence: `authTokens[host:login:github].token`, `authTokens[host:login].token`, then `copilotTokens[host:login]`. Absent or empty file tokens read the selected account's exact Credential Manager target through the native addon on Windows, or the `copilot-cli` Keychain service through bounded, cancellable `/usr/bin/security` on macOS. Config errors and invalid tokens fail without CLI, ambient-token or other-account fallback; `copilot-cli` remains an explicit option.
- **Node.js ≥ 24** for every package (`engines.node`).
- **Dependency audits:** production audits stay strict. Reviewed advisory exceptions in `scripts/ci-npm-audit.sh` apply only to development dependencies with no patched release; remove them when a fix is available.
- **SSE infrastructure:** CoC server, SPA, and container consumers share `@plusplusoneplusplus/forge/sse`; CoC writers import its `server/shared/sse-writer.ts` re-export. Process stores share `createProcessEventBus()` from forge. See the knowledge skill's `references/streaming-architecture.md` for framing and lifecycle contracts.
- **Never switch the active branch:** AI must NEVER change the active branch identity or detach HEAD in the worktree where the session started, including via `git checkout` or `git switch`. Authorized commits, pulls, merges, and rebases on the current branch may update HEAD without switching branches. Preserve unrelated edits and never perform destructive actions without explicit approval. Purpose-built workflows may create and use a temporary linked worktree on another branch; all branch-switching operations must stay inside that isolated worktree, and the active worktree's branch identity must remain unchanged.
